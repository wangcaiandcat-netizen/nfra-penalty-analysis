# 服务就绪检查

## 本地脚本环境先检查

每次业务命令用统一入口，自动在加载业务代码和API调用前检查Python版本、标准库及安装文件；导出额外检查输出目录，失败返回具体修复提示。Windows优先直接用已有Python执行scripts/run.py，run.cmd仅为可选便捷入口；平台移除run.cmd时无需补起任何后台服务。完整命令与按报错检索表见 [环境预检与Excel导出](excel-export.md)。检查过程不读取.env、不发网络请求；正常查询无需先手工执行一轮检查。

独立排错：`python -B -X utf8 scripts/run.py check`，导出加`--task export --output 任务目录/台账.xlsx`。通过不表示后台已就绪，再按下文执行catalog。

## 从宿主实际调用环境检查

先使用同一宿主解释器、同一服务地址读取处罚目录：

```bash
python3 -B -X utf8 scripts/run.py catalog
```

Windows可用 `python`。默认地址是 `https://deepfin.vip`，正常情况下不先检查环境或扫描端口。成功取得 `scope`、`regions`、`business` 等目录才表示处罚API可访问；读取覆盖范围、修订及派生标签状态。不能把端口响应或其他服务的HTTP200当成处罚查询就绪。

有连接问题时可进一步执行以下只读检查。命令针对默认生产服务；明确使用其他地址时检查那个地址，不切换到其他服务：

```bash
curl --fail --show-error --max-time 10 https://deepfin.vip/health
curl --fail --show-error --max-time 10 https://deepfin.vip/ready
python3 -B -X utf8 scripts/run.py catalog
```

Windows PowerShell使用 `curl.exe`。`/health` 的服务标识应为 `deepfin-api`；它只检查进程存活。`/ready` 检查数据库、迁移表、存储和配置等应用依赖；503时由后台维护者处理，不能由Skill修改配置。最终仍以处罚 `catalog` 和目标查询的实际响应判断该功能是否可用，尤其是标签缓存相关503。

## 本地后台联调

此公开项目只提供客户端。自建后台的启动、配置和维护由后台维护者依据自己的部署文档完成；Skill 查询任务不自动启动或重启后台，不读取其 `.env`，也不启动处罚采集任务。

已有本地处罚服务时，可显式传入 `--base-url http://127.0.0.1:8002`，实际端口以维护者配置为准。启动本地后台不会改变 Skill 的生产默认地址，检查时沿用明确指定的服务，不自动扫描端口或切换地址。

## 连接失败最常见的三类原因

| 原因 | 可观察现象 | 处理 |
|---|---|---|
| 所选服务不可用，或本地联调入口与显式端口不一致 | `NETWORK_ERROR`，所选地址的health也失败 | 生产环境由维护者检查HTTPS入口与服务；本地联调核对实际启动入口和端口，不自动枚举端口 |
| 宿主与后台不在同一网络环境 | 浏览器能访问，但Workbuddy、WSL或容器里的同一地址不能访问 | 从实际客户端环境检查已有代理与NO_PROXY及可达性；不自行改地址、网络或安全设置，不创建转发或后台重试服务 |
| 地址覆盖值错误或服务路径不匹配 | `INVALID_BASE_URL`、`INVALID_BASE_PATH`，或返回其他应用/404 | 让用户核对显式地址或已配置的覆盖值；接受服务根或完整处罚前缀，不搜索本机密钥/配置文件 |

以下是**已连接后的服务错误**，不要统称“连不上”：401 `AUTH_REQUIRED`按返回链接提示用户登录；403说明权限不足；409需要重新查询并取得新修订；429遵守等待时间；503可能是应用依赖、访问暂停或分类/辖区派生数据尚未就绪，按对应响应说明。不得因此换身份、换路径、启动采集或频繁重试。

## 预演不是健康检查

`--dry-run` 不访问服务，即使后台关闭也能通过。用它核对归一化请求，用真实 `catalog`/目标响应确认服务可用；不要以预演通过宣称接口联调成功。
